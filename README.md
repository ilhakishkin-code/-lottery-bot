# Telegram-бот для розыгрышей

Каркас бота на **aiogram 3** + **SQLite**. Реализовано:

## Роли в боте

- **Владелец канала** — любой, кто добавил бота в свой канал и создал розыгрыш через `/new_lot`. Он проходит мастер создания и публикует пост, но **не видит** ни список участников, ни победителей, ни статистику — доступа к этим данным у него нет.
- **Админ бота** — это вы (задаётся вашим личным Telegram id в `ADMIN_IDS`). Только вы видите, кто участвует, статистику по каналам, и только вы выбираете победителей и шлёте им сообщения. Кто угодно другой, даже владелец канала, на команды `/giveaways` и `/stats` не получит вообще никакого ответа — бот делает вид, что этих команд не существует.

## Функциональность

- пользовательский сценарий: кнопка «Участвовать» под постом → `/start` в ЛС → регистрация участия;
- `/new_lot` — пошаговый мастер создания розыгрыша:
  1. Пересылаете боту любое сообщение из канала — так бот узнаёт канал и проверяет права.
  2. Присылаете сам пост боту в личку (текст/фото/видео/гифка — что угодно, с любым форматированием и анимированными эмодзи).
  3. Выбираете текст кнопки, число победителей, дату итогов.
  4. Бот присылает вам обратно **готовое превью с кнопкой прямо в личке** — со всей анимацией (это разрешено Telegram в личных чатах).
  5. Вы пересылаете это превью в канал. Кнопка при пересылке пропадает (особенность Telegram) — бот сам её тут же возвращает, автоматически заметив новый пост в канале.
  6. Если автоматика почему-то не сработала — можно просто переслать уже опубликованный пост из канала боту вручную, он прикрепит кнопку тем же способом (запасной вариант);
- `/end_lot` — досрочно завершить **свой собственный** розыгрыш (снимает кнопку с поста) — доступно любому создателю, не только ADMIN_IDS, но без доступа к участникам;
- `/giveaways` — список **всех** розыгрышей по всем каналам сразу, с указанием, кто из владельцев его создал — **только для ADMIN_IDS**;
- `/stats` — сводная статистика «в каком канале сколько человек нажали Участвовать» по всем каналам — **только для ADMIN_IDS**;
- «📣 Напомнить всем об итогах» — рассылка всем участникам конкретного розыгрыша с отчётом о доставке — **только для ADMIN_IDS**;
- выбор победителя вручную по `@username` или `id` — **только для ADMIN_IDS**; победителю приходит сообщение с контактом из `PRIZE_CONTACT_USERNAME` (см. ниже);
- кнопка повторного напоминания победителю — **только для ADMIN_IDS**;
- заглушка вместо обязательной подписки на каналы — специально не реализована, как договаривались, это следующий этап;
- `/reset_all` — полностью очищает базу (все каналы, розыгрыши, участников, победителей, пользователей) с подтверждением на кнопке — **только для ADMIN_IDS**.

Цвет кнопки и подтверждение прочтения сообщения по договорённости из ТЗ убраны — кнопка под постом теперь просто с выбранным текстом, а сообщения победителю и напоминание отправляются как обычный текст.

Все команды и кнопки, требующие ADMIN_IDS, а также весь мастер `/new_lot`/`/end_lot` работают **только в личке с ботом** — если их случайно набрать в группе или обсуждении при канале, бот там просто не ответит.

## Права бота в канале

Боту нужно право **«Редактировать сообщения других участников»** (в настройках администраторов канала в Telegram) — им бот прикрепляет кнопку к посту, который вы сами переслали в канал.

## Почему анимированные премиум-эмодзи теперь работают

Официальное ограничение Telegram Bot API: боты могут использовать кастомные (анимированные) эмодзи в сообщениях, которые отправляют **сами**, только в личку/группу/супергруппу (и только если у владельца бота есть Premium) — но никогда в канал, если у бота нет купленного через Fragment username. Это ограничение касается именно того, что БОТ САМ отправляет сообщение с этими эмодзи в канал — неважно, каким методом (`sendMessage`, `copyMessage` и т.п.).

Наш способ: бот присылает вам превью с анимацией и кнопкой **в личку** (это разрешено), а в канал сообщение попадает через **вашу собственную пересылку** — то есть публикует его фактически ваш аккаунт, а не бот. Правило Telegram сюда не применяется. Кнопка при пересылке слетает — но бот тут же обнаруживает новый пост в канале (через `channel_post`-событие) и прикрепляет рабочую кнопку через `editMessageReplyMarkup`, не трогая текст/анимацию.

## Как настроить ADMIN_IDS

1. Напишите боту [@userinfobot](https://t.me/userinfobot) — он пришлёт ваш числовой Telegram id.
2. Впишите его в переменную `ADMIN_IDS` (в `.env` локально или в переменных окружения на хостинге). Несколько доверенных id — через запятую: `ADMIN_IDS=111111111,222222222`.
3. Без этой переменной бот вообще не запустится — так специально сделано, чтобы никто случайно не выложил бота без единого админа.

## Кто выбирает победителя и кто выдаёт приз — это разные роли

- **ADMIN_IDS** — кто видит участников, статистику и жмёт кнопку «Выбрать победителя».
- **PRIZE_CONTACT_USERNAME** — чей @username бот покажет победителю в духе «за призом пишите сюда» (и в напоминании). Это может быть отдельный человек, который физически выдаёт призы — не обязательно тот же, кто выбирает победителей.

Если `PRIZE_CONTACT_USERNAME` не задан — бот подставит username того админа, кто в данный момент нажал кнопку (как временное поведение по умолчанию). Если у вас есть отдельный менеджер по призам — обязательно впишите его username в эту переменную.

## Установка на bothost.ru

Bothost разворачивает ботов из Git-репозитория, а не из архива — сначала залейте код на GitHub/GitLab.

```bash
cd lottery_bot
git init
git add .
git commit -m "init"
git remote add origin <ссылка на ваш репозиторий>
git push -u origin main
```

`.env` в репозиторий заливать не нужно (и не стоит — там секретный токен), он уже в `.gitignore`-логике: просто не добавляйте его в коммит. Токен и `ADMIN_IDS` передаются через переменные окружения панели Bothost.

Дальше:

1. Зарегистрируйтесь на [bothost.ru](https://bothost.ru) и откройте `create-bot.php`.
2. Платформа — Telegram, библиотека — Aiogram 3.x, Bot Token — из @BotFather, Git URL — ссылка на репозиторий, ветка `main`.
3. Точку входа указывать не нужно — Bothost сам найдёт `bot.py`.
4. В переменных окружения добавьте:
   - `DB_PATH=/app/data/lottery_bot.db` — важно: всё, что лежит вне `/app/data`, стирается при каждом обновлении кода из Git, а там как раз наша SQLite-база с участниками и победителями;
   - `ADMIN_IDS=ваш_telegram_id` — без неё бот не стартует.
5. Нажмите «Создать бота», дождитесь деплоя, проверьте логи — там должен появиться успешный старт polling без ошибок.
6. Для реального использования (не тестов) возьмите тариф Active — на бесплатном Start есть «спящий режим», не годится для розыгрыша, который должен работать непрерывно.

## Установка на обычный VPS

Подходит любой недорогой VPS (Ubuntu 22.04/24.04, 1 vCPU / 512 МБ-1 ГБ RAM с запасом хватит с головой).

```bash
# 1. Устанавливаем Python 3.11+ и git, если их ещё нет
sudo apt update && sudo apt install -y python3 python3-venv python3-pip git

# 2. Загружаем код на сервер (например, через scp/git) и переходим в папку
cd lottery_bot

# 3. Создаём виртуальное окружение и ставим зависимости
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 4. Настраиваем токен бота и админа
cp .env.example .env
nano .env   # вписываем BOT_TOKEN (от @BotFather) и ADMIN_IDS (ваш id от @userinfobot)

# 5. Пробный запуск
python bot.py
```

Если всё стартовало без ошибок и бот отвечает на `/start` — переходим к постоянной работе через systemd, чтобы бот жил после закрытия SSH-сессии и перезапускался сам при падении/перезагрузке сервера.

### systemd-сервис (бот работает даже когда ваш ПК выключен)

Создайте файл `/etc/systemd/system/lottery_bot.service`:

```ini
[Unit]
Description=Telegram lottery bot
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/lottery_bot
ExecStart=/home/ubuntu/lottery_bot/venv/bin/python bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

(поправьте `User` и пути под вашего пользователя и расположение проекта)

```bash
sudo systemctl daemon-reload
sudo systemctl enable lottery_bot
sudo systemctl start lottery_bot

# проверить статус / логи
sudo systemctl status lottery_bot
journalctl -u lottery_bot -f
```

С этого момента бот работает на сервере 24/7 независимо от вашего компьютера.

## Что важно донастроить перед реальным использованием

- **ADMIN_IDS обязателен** — без него бот вообще не запустится (сделано намеренно, чтобы не забыть настроить админа).
- **Права канала**: бота нужно добавить в канал администратором с правом «Публикация сообщений» — иначе `/new_lot` откажется подключать канал (это защита, а не баг).
- **Обязательная подписка на каналы** (шаг 8 из ТЗ) — сознательно не реализована, задел под неё есть в схеме БД и в шагах мастера, добавим следующим этапом.
- **Автоматическое случайное определение победителей по дате итогов** — в текущем ТЗ это была «формальность», победителей вы выбираете вручную по `@username`/`id`; поле даты сейчас чисто информационное (отображается в карточке розыгрыша). Если в будущем понадобится авто-розыгрыш по таймеру на указанную дату — это добавляется отдельным фоновым планировщиком (APScheduler), легко встраивается в текущую архитектуру.
- **SQLite → PostgreSQL**: если розыгрышей и участников станет очень много (десятки тысяч+), стоит перейти на PostgreSQL — весь SQL-код изолирован в `database.py`, миграция не потребует переписывать хендлеры.

## Структура проекта

```
lottery_bot/
├── bot.py                  # точка входа, регистрация роутеров, polling
├── config.py                # токен, ADMIN_IDS, пресеты текста кнопки
├── database.py               # вся работа с SQLite
├── states.py                  # FSM-состояния мастера и выбора победителя
├── keyboards.py                # инлайн-клавиатуры
├── utils.py                     # парсинг даты/времени МСК
├── handlers/
│   ├── user.py                    # /start, регистрация участия
│   ├── admin_new_lot.py             # мастер /new_lot — доступен любому владельцу канала
│   └── admin_panel.py                 # /giveaways, /stats, выбор победителя, напоминания — только ADMIN_IDS
├── requirements.txt
└── .env.example
```
